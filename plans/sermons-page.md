# Plan: Sermons page and sermon data job

Status: implemented (October 2026), pending the GOOGLE_API_KEY secret and first workflow run. Written so an implementer with no other context can build it.

## Goal and scope

Replace the "Sermons" links (which currently go to the YouTube channel's Streams tab) with a real **Sermons page** (`sermons.html`) that shows:

1. **Recent services**: the 6 newest YouTube live-stream recordings as cards (thumbnail, date, links). When a recording's date matches a sermon in a Drive series folder, the card also shows that sermon's title, passage, and links to its notes (PDF) and audio (MP3).
2. **Sermon series**: one expandable card per series (from Google Drive), listing every sermon with its number, date, title, passage, and Notes / Audio / Video links.

The data comes from a **scheduled GitHub Actions job** that reads the YouTube Data API and the Google Drive API (with one free Google API key), reads titles/passages from the notes PDFs, and commits `data/sermons.json`. The page loads that JSON in the browser.

**Out of scope (deliberately deferred):**
- **Summaries.** The JSON has a `summary` field (always `null` for now) on every video, sermon, and series, and the page displays it when present. Summaries can later be filled in by hand in the series file, or generated by AI (e.g. Claude API from YouTube transcripts or the PDF notes).
- **Gospel of John series.** Its Drive folder (`0B-mo4R1ry-JBakM1N3ZYUFAwams`) is private (requires sign-in). Leave it out of the series file. It can be added once someone sets it to "Anyone with the link can view".
- A full browsable video archive on our site (only the 6 newest; "See all on YouTube" covers the rest).
- Embedded video players on the Sermons page (cards link out to YouTube).

## Decisions

| Decision | Choice | Why |
| --- | --- | --- |
| Data source | Official YouTube Data API v3 + Google Drive API v3 with one API key (GitHub secret `GOOGLE_API_KEY`) | Reliable, full history, no scraping of pages that change or cap at ~30-50 items. |
| Summaries | Deferred; `summary: null` fields everywhere, page shows them when present | Keeps scope small; the data shape is ready for AI or hand-written summaries later. |
| Series list | Hand-edited `data/series.json` in the repo | Series folders are scattered (no shared parent). Adding a series = add one entry. |
| Gospel of John | Left out for now | Folder is private. |
| Recent videos | Card grid of the **6** newest, linking out to YouTube | Light page, no embedded players; home page already embeds the latest service. |
| Series display | Expandable cards (`<details>`) listing every sermon with Notes / Audio / Video links | Everything for a series in one place without extra pages. |
| In-progress series | `"current": true` in the series file: listed first with a "Current series" label | Recent video cards pick up Notes/Audio as files appear. |
| Titles/passages | Read from the notes PDF header, best-effort, cached per file; overridable in the series file | Real titles make the list useful; no AI needed. |
| Rendering | Browser loads `data/sermons.json` via `assets/js/sermons.js` | Data and design stay separate; JSON reusable by other pages later. |
| Job schedule | Daily, plus manual "Run workflow" | Sunday's stream appears the same day; cheap (API use is tiny). |
| Job language | Node.js (CommonJS, like the existing tests), built-in `fetch` | Node is already used for tests; one toolchain. |
| Failure policy | If any source fails, write nothing and exit non-zero | The site keeps the last good JSON; GitHub emails the repo owner about the failed run. |
| Which videos | Completed live streams (and a "Live now" card while one is live); never upcoming/scheduled; `hiddenVideos` list in the series file to exclude specific ones | Live streams are where sermons go. |
| Video date | Stream's `actualStartTime` in `America/Los_Angeles`; fallback: `MM/DD/YYYY` in the title; fallback: `publishedAt` (Pacific) | Avoids UTC making Sunday evening streams look like Monday. |
| Matching | A video matches a sermon when their dates are equal (across all series) | File names and stream titles both carry the service date. |

## Global constraints (apply to every task)

- Static site on GitHub Pages, no build step for the site. Plain HTML/CSS/JS; relative links only (no leading `/`).
- Follow the repo's `CLAUDE.md` testing rules: every task adds/updates Playwright tests in `tests/`, each test file starts with the FEATURE / COVERS / WHY / UPDATE WHEN / REMOVE WHEN header, normal tests import `test`/`expect` from `tests/support/fixtures.js`, outside services are faked, live checks go in `tests/live/`. Run `npm test` before finishing; it must pass on both `desktop` and `mobile` projects.
- Never commit API keys. The key is only read from the `GOOGLE_API_KEY` environment variable.
- Pin any new npm dependency to an exact version released at least two weeks earlier.
- Match existing code style: 2-space indent in JS, `const`/arrow functions, small comments explaining *why*; CSS uses the `:root` variables in `assets/css/base.css` (`--bg`, `--surface`, `--ink`, `--muted`, `--brand`, `--brand-ink`, `--accent`, `--line`, `--serif`, `--sans`, `--r`) so dark mode works automatically.
- Dates in JSON are `YYYY-MM-DD` strings. In the browser, never parse them with `new Date('YYYY-MM-DD')` (that's UTC and shifts the day); build dates from the parts and format with `timeZone: 'UTC'`.
- The JSON shape below is the contract between the job and the page. Both sides must follow it exactly.

## Design

### Files

```
data/
  series.json             Hand-edited: series list and overrides (input to the job)
  sermons.json            Generated by the job (committed); read by the page
  cache/pdf-headers.json  Generated: parsed PDF headers keyed by Drive file ID (avoid re-downloading)
scripts/build-sermons/
  index.js                Entry point: loads config, calls sources, builds, validates, writes
  youtube.js              YouTube Data API calls
  drive.js                Drive API calls (list folder, download file)
  pdf.js                  Extract first-page text from a PDF buffer
  build.js                Pure functions: parse names, group files, parse headers, dates, matching, assemble
  validate.js             Validates a sermons.json object against the schema (used by job and tests)
sermons.html              The page
assets/css/sermons.css    Page styles
assets/js/sermons.js      Loads data/sermons.json and renders the page
.github/workflows/update-sermons.yml   Daily job
```

### `data/series.json` (hand-edited input)

```json
{
  "hiddenVideos": [],
  "series": [
    {
      "id": "james",
      "title": "James",
      "folder": "https://drive.google.com/drive/folders/10qhMfF2NgGNnmGcpaVqIX7nIDKNqtx5l",
      "current": false,
      "summary": null,
      "overrides": {}
    }
  ]
}
```

- `id`: lowercase slug, unique, used as the HTML anchor (`#series-james`).
- `folder`: full Drive folder URL; the job extracts the ID with `/folders\/([\w-]+)/`.
- `current`: optional, default `false`. At most one series should be current (if several, all are shown first, newest first).
- `summary`: optional string, copied into the output.
- `overrides`: optional, keyed by the file base name without extension (e.g. `"001 01-09-22"`), each `{ "title"?: string, "passage"?: string, "summary"?: string }`. Overrides win over PDF-parsed values.
- `hiddenVideos`: YouTube video IDs to leave out of `recent` and matching.
- Initial content: the four public series above (James, Jude, Second Peter, First Peter), all `current: false`, in that order.

### `data/sermons.json` (generated; the contract)

```json
{
  "version": 1,
  "generatedAt": "2026-10-21T22:00:00.000Z",
  "streamsUrl": "https://www.youtube.com/@southclackamascommunitychu1171/streams",
  "recent": [
    {
      "videoId": "6zuVPimQvxU",
      "url": "https://www.youtube.com/watch?v=6zuVPimQvxU",
      "thumbnail": "https://i.ytimg.com/vi/6zuVPimQvxU/hqdefault.jpg",
      "date": "2026-10-18",
      "youtubeTitle": "SCCC 10/18/2026",
      "live": false,
      "summary": null,
      "sermon": null
    }
  ],
  "series": [
    {
      "id": "james",
      "title": "James",
      "current": false,
      "folderUrl": "https://drive.google.com/drive/folders/10qhMfF2NgGNnmGcpaVqIX7nIDKNqtx5l",
      "summary": null,
      "firstDate": "2022-01-09",
      "lastDate": "2022-12-18",
      "sermons": [
        {
          "key": "001 01-09-22",
          "number": "1",
          "date": "2022-01-09",
          "title": "You Can Have Joy No Matter What",
          "passage": "James 1:1-4",
          "notesUrl": "https://drive.google.com/file/d/<pdfId>/view",
          "audioUrl": "https://drive.google.com/file/d/<mp3Id>/view",
          "videoUrl": null,
          "summary": null
        }
      ]
    }
  ]
}
```

Rules:
- `recent`: at most 6, newest first. `live: true` for a stream currently live (date = today, Pacific). `sermon` is `null` or `{ "seriesId", "seriesTitle", "number", "title", "passage", "notesUrl", "audioUrl" }` for the matched sermon (title/passage/urls may be `null`).
- `series`: order = current series first, then the rest by `lastDate` descending (newest series first). A series with no parsable files still appears with `sermons: []`, `firstDate`/`lastDate` `null`.
- `sermons`: sorted by date ascending, then numerically by number. `number` is the file's number with leading zeros removed (`"001.5"` → `"1.5"`). `title`/`passage`/`notesUrl`/`audioUrl`/`videoUrl` are `null` when unknown/missing. `videoUrl` = the matching stream's URL (any date match, not only recent).
- Audio files: extensions `mp3`, `m4a`, `wav`. Notes: `pdf`. If two files share a key and type, take the most recently modified and log a warning.

`validate.js` exports `validateSermons(obj)` returning an array of error strings (empty = valid). It checks: `version === 1`; every required key above present with the right type (`string`/`boolean`/`null`/array); dates match `^\d{4}-\d{2}-\d{2}$`; URLs start with `https://`; `recent.length <= 6`; series IDs unique.

### The job (`scripts/build-sermons/`)

Run with `npm run sermons` (add `"sermons": "node scripts/build-sermons/index.js"` to `package.json`). Requires `GOOGLE_API_KEY`; exits with a clear message if missing.

**`youtube.js`**: `listStreams(key, fetchImpl = fetch)`:
1. `GET https://www.googleapis.com/youtube/v3/playlistItems?part=contentDetails&maxResults=50&playlistId=UU1Svz8uLW3raCDDP9I1eg_A&key=…`, following `nextPageToken` until done, collecting `contentDetails.videoId`.
2. `GET https://www.googleapis.com/youtube/v3/videos?part=snippet,liveStreamingDetails&id=<up to 50 comma-separated>&key=…` in batches.
3. Keep videos with `liveStreamingDetails` where either `actualEndTime` is set (completed) or `snippet.liveBroadcastContent === 'live'` (live now). Drop upcoming/scheduled and regular uploads.
4. Return `[{ videoId, title, publishedAt, actualStartTime, live }]`.
Throw on any non-200 response with the API's error message.

**`drive.js`**:
- `listFolder(folderId, key, fetchImpl)`: `GET https://www.googleapis.com/drive/v3/files?q='<id>' in parents and trashed=false&fields=nextPageToken,files(id,name,mimeType,modifiedTime)&pageSize=1000&key=…`, following `nextPageToken`. A 403/404 means the folder isn't public: throw an error naming the series.
- `download(fileId, key, fetchImpl)`: `GET https://www.googleapis.com/drive/v3/files/<id>?alt=media&key=…` → `Buffer`.
- File view URL: `https://drive.google.com/file/d/<id>/view`.

**`pdf.js`**: `firstPageText(buffer)` → string with line breaks, using the `unpdf` package (`extractText`, first page only; join text items, inserting newlines where items have `hasEOL` or y-position changes). Add `unpdf` as a dependency (not dev) pinned per the global constraints.

**`build.js`** (pure, no network; all unit-tested):
- `parseFileName(name)` → `{ key, number, date, kind: 'audio'|'notes' }` or `null`. Regex: `/^(\d+(?:\.\d+)?)\s+(\d{2})-(\d{2})-(\d{2})\.(mp3|m4a|wav|pdf)$/i`; `date = 20YY-MM-DD`; reject impossible dates (e.g. `13-40-22`).
- `groupFiles(files)` → `{ sermons: Map<key, {key, number, date, notesFile?, audioFile?}>, warnings: string[] }`. Unparsable names produce a warning `Skipped "<name>" in <series>: name doesn't match "NNN MM-DD-YY.ext"` (ignore Google-native types like folders/Docs silently but warn about them too).
- `parseNotesHeader(text)` → `{ title, passage }` (either may be `null`). Lines = trimmed non-empty lines of the first page. Passage: first line matching `/^Text:\s*(.+)$/i`, capture trimmed. Title: the first line after a line matching `/#\s*\d/` (the "James #1" line) that is not a date (`/^[A-Z][a-z]+ \d{1,2}, \d{4}$/`) and not the `Text:` line; if no `#` line, `null`. Titles longer than 120 characters → `null` (probably not a header).
- `videoDate(video)` → `YYYY-MM-DD` in `America/Los_Angeles` from `actualStartTime` (use `Intl.DateTimeFormat('en-CA', { timeZone: 'America/Los_Angeles' })`), else from `/(\d{1,2})\/(\d{1,2})\/(\d{4})/` in the title, else `publishedAt` in Pacific.
- `assemble({ config, streams, folders, headers })` → the `sermons.json` object (without `generatedAt`; `index.js` adds it). `folders` = `{ [seriesId]: files[] }`, `headers` = `{ [fileId]: { title, passage } }`. Applies overrides, hidden videos, matching, ordering, date ranges, `recent` (6 newest after hiding).

**`index.js`**:
1. Read `data/series.json`, `data/cache/pdf-headers.json` (missing = `{}`).
2. Fetch streams and every series folder (sequentially or with small concurrency). Any error → print it and `process.exit(1)` before writing anything.
3. For each notes PDF whose `id` + `modifiedTime` isn't in the cache: download, extract text, `parseNotesHeader`, store `{ modifiedTime, title, passage }`. A failed parse of one PDF is a warning, not a failure (title/passage stay `null`).
4. `assemble`, add `generatedAt`, run `validateSermons`; if errors, print and exit 1.
5. Write `data/sermons.json` and the cache with `JSON.stringify(obj, null, 2) + '\n'`. To avoid a commit every day when nothing changed, keep the previous `generatedAt` if everything else is identical.
6. Print warnings, and if `GITHUB_STEP_SUMMARY` is set, append them as a Markdown list so they show on the run page.

### Workflow (`.github/workflows/update-sermons.yml`)

```yaml
name: Update sermon data
on:
  schedule:
    - cron: '0 22 * * *'   # daily, 3 pm Pacific (daylight) / 2 pm (standard), after Sunday's stream
  workflow_dispatch:
permissions:
  contents: write
concurrency: update-sermons
jobs:
  update:
    runs-on: ubuntu-latest
    timeout-minutes: 15
    steps:
      - uses: actions/checkout@v4
      - uses: actions/setup-node@v4
        with: { node-version: 22, cache: npm }
      - run: npm ci
      - run: npm run sermons
        env:
          GOOGLE_API_KEY: ${{ secrets.GOOGLE_API_KEY }}
      - name: Commit if changed
        run: |
          if git diff --quiet -- data/; then echo "No changes"; exit 0; fi
          git config user.name "github-actions[bot]"
          git config user.email "41898299+github-actions[bot]@users.noreply.github.com"
          git add data/sermons.json data/cache/pdf-headers.json
          git commit -m "Update sermon data"
          git push
```

## Edge cases and error handling

- Drive folder becomes private or deleted → job fails with the series name; site keeps last data; owner gets GitHub's failure email.
- API key missing/invalid/quota exceeded → job fails clearly; same.
- Misnamed Drive files, Google Docs in a folder, duplicate files → skipped/kept-newest with warnings on the run summary page.
- PDF that's scanned (no text) or a different header format → title/passage `null`; sermon still listed by number and date.
- Two streams on the same date (e.g. a special service) → both appear in `recent`; matching uses the earliest-started stream for the sermon's `videoUrl`.
- Stream that started late Sunday Pacific (Monday UTC) → dated Sunday via Pacific conversion.
- Series with zero parsable files → shown with "0 sermons" meta omitted to just the title and folder link.
- JSON fails to load in the browser, or is opened via a double-clicked file → error messages with a YouTube link; no uncaught errors.
- Very long titles/passages → wrap; no horizontal scroll on phones.
